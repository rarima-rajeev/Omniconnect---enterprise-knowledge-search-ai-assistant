## Overview

The AskWell platform has four main layers: connectors, the index, the permission engine and the gateway API. A user's question enters through the gateway, is checked against their identity, is answered from the index using only content they are allowed to see, and is returned to the calling assistant with citations.

## Connectors

Connectors pull content from source systems such as SharePoint, ServiceNow, Confluence, Salesforce and Workday. Each connector runs on a schedule and also listens for change events. Along with the content, connectors copy each item's access control list (ACL): which users and groups are allowed to read it. Connectors never store credentials of end users; they use service accounts with read-only scopes approved by the customer.

## Index

Content is split into passages and stored with vector embeddings and keyword indexes. Each passage carries the ACL of its parent item, so permissions travel with the content. The index runs on Postgres with the pgvector extension, partitioned by customer tenant.

## Permission engine

The permission engine resolves a user's identity into the full set of groups and roles they belong to, using the customer's identity provider (usually Entra ID or Okta). Group memberships are cached for five minutes. Every search is filtered by these memberships inside the database query itself, so content a user cannot see is never returned to the application layer.

## Gateway API

The gateway authenticates the calling assistant with OAuth, identifies the end user from a signed token, runs the permission-filtered search, and sends the top passages to the language model with instructions to answer only from those sources and cite them. All requests are logged to the audit trail with the user, the query and the documents returned.

## Reliability

The platform runs in three AWS regions (us-east-1, eu-west-1 and ap-south-1). Each region has a primary Postgres cluster with a synchronous standby and asynchronous read replicas. Redis is used for session storage and short-lived caches. Our availability target is 99.95% per month.

## Observability

Metrics go to Datadog, logs to OpenSearch and traces to Honeycomb. Every query records latency at each stage, the number of passages retrieved and the number filtered by permissions.
